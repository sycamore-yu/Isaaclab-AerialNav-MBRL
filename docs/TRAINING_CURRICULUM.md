# 训练课程与验收

2026-10-29：按本轮要求替换原先的固定 100 障碍、2200 次更新和独立评测协议。

两个任务使用 350 个静态障碍物。动态障碍课程为 60→80→100→120。当前阶段的训练成功率超过 80% 后晋级。验收采用 100 障碍阶段的训练成功率，目标约 80%；达到目标时保存该阶段的最佳策略。随后继续训练 120 阶段。正式训练从随机初始化开始，不设置优化更新次数上限。

`run_acceptance.py --method both` 按顺序运行 NavRL 和 Zhang。正式入口传入 `--stop_after_acceptance`：100 阶段达标且完成首次 120 阶段训练统计后结束该方法，再启动下一方法。120 阶段不增加成功率门槛。直接调用训练脚本时默认持续训练；`--max_iterations` 只用于短检查。任何方法正常通过前，顺序入口都不会跳到下一方法。

课程数量和晋级阈值来自 NavRL 论文 IV-A。论文报告 100 障碍阶段的最高训练成功率为 80.96%。来源：https://arxiv.org/html/2409.15634v2 。本地上游提交 `3725bcc` 的 `train.py` 没有自动课程切换；其 `EpisodeStats` 在累计完成至少 `num_envs` 个训练回合后汇总并清空。迁移沿用这一汇总频率。正式运行时 `num_envs=1024`。没有独立评测环境，也不添加平滑窗口或连续多窗口达标要求。

每回合只记录一个首次结果：成功、碰撞、高度越界、无效状态或超时。成功指碰撞前首次进入目标 0.5 m 范围。成功后继续遵循原任务终止规则；自然回合结束时计入统计。保留原 `reach_goal` 日志，不将该即时值替换为课程成功率。Zhang 使用已实现的物理子步首次事件。统计记录实际回合数和成功到达时间。

每个阶段同时记录 `episode_return_mean`、`episode_length_mean` 和 `reward_per_step_mean`。前两项按同批完成回合数加权；最后一项用同批回合总 return 除以总策略步数。环境在累计当前步奖励后、自动重置前保存数值，因此包含终止步奖励。Zhang 仅记录 NavRL 奖励，策略更新仍使用其独立损失。

同一场景预先创建 120 个动态物体。每阶段按原尺寸类别选取相应数量，并用该数量重建原采样分布。未激活物体移到相机范围外，不进入观测、几何碰撞或损失。课程切换发生在优化更新边界。全部无人机开始新回合，清空对应的时序历史，避免混合不同难度的回合；模型和优化器保持连续。

Zhang 保持深度相机、原损失、100 Hz 物理频率、10 Hz 策略频率和 150 策略步展开。速度窗口保持 60 策略步。按本轮初始 2000 次更新内 5 个周期配置，余弦调度每 400 次更新循环一次。2000 次后每增加 500 次检查进度；训练进程、模型和优化器连续运行，不设更新上限，不加载检查点续训。

1024 环境的首轮 Zhang 检查因显存不足而退出。训练网络改用 PyTorch 非重入激活检查点，在反向传播时重算 CNN 与 GRU 中间量。PhysX、深度图、损失、展开长度和网络权重结构保持原样。CPU 递归序列对照中，输出、参数梯度和状态输入梯度逐元素相等。参考：https://docs.pytorch.org/docs/2.11/checkpoint.html 。
