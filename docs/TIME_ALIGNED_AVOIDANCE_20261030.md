# 动态前视修复与六组微调 S1 对照

动态障碍和无人机现在使用相同的前视时刻。基线包含此修复；EMA、横向避障、风险降速和 SDF 保持为对照选项。正式五阶段验收仍使用原课程顺序。

## 距离和速度

前视点为 `p_u + v_u * tau`，动态障碍位置为 `p_o + v_o * tau`。20 Hz 下，10 个查询点覆盖 0–50 ms。DCOL 的 8 个中间点使用对应时刻的障碍位置。最后一个点仍取首次碰撞子步的位置；无碰撞时取物理步末位置。静态地形和地面公式不变。

动态预测假设一个策略步内速度不变。障碍物随后改向时，预测与实际轨迹会有差异。终端损失不使用此预测。动态 SDF 选择支持共享位置和逐查询位置；AHAC 的米制风险距离调用同一个函数。

SDF 法线 `n` 朝障碍外部，接近速度为 `-(v_u-v_o)·n`。静态障碍和地面的速度为 0。显式相对速度替换距离差分权重，保留原来的下限 1 和 detached 权重。基础距离惩罚因此不会因远离障碍而消失。修复时间后，距离差分本身已近似包含相对速度。

横向项参考固定版本 [DiffAero 障碍损失](https://github.com/flyingbitac/diffaero/blob/291ea14196aefbebcf7387dd71f7e096c83878b7/env/obstacle_avoidance.py)。新增项为风险加权的正接近速度减去 0.5 倍水平切向速度。查询点中接近风险最大的点决定该项。只在接近侧面时奖励水平切向速度；竖直速度不获此奖励，地面法线也不触发横向奖励。风险权重和法线截断梯度，避免负奖励吸引无人机靠近障碍。本项目沿用最近障碍查询，不等同于 DiffAero 对每个障碍求最大值的完整目标。

P3 使用 `exp(-max(clearance, 0)) * max(closing, 0) / max_speed` 表示风险。风险裁到 0–1，再将目标速度比例从 1 降到最低 0.25。该比例不传播梯度。基础速度损失仍保留原 2 秒窗口及目标索引语义，所以窗口监督仍有延迟。

## EMA 速度

EMA 采用 `vbar = lerp(vbar, measured_post_step_velocity, alpha)`。每个环境、每次 episode 重置时，从 0.08–0.12 均匀采样 alpha。采样使用独立随机数流，不改变环境扰动的采样序列。

终止步先计入旧 episode 的速度损失，再清零对应 EMA。更新边界保留 EMA 数值并截断梯度。EMA 模式每步都有速度监督，速度误差仍使用 Smooth L1。若与 SHAC 组合，critic 额外接收 EMA 和 alpha。20 Hz 下，该范围的时间常数约为 0.39–0.60 秒；这与基线 2 秒完整窗口是不同的监督设计。

## 六组配置

权威配置为 [zhang_finetune_s1.json](../configs/experiments/zhang_finetune_s1.json)。共同场景为 `finetune_s1`：300 个静态障碍、60 个动态障碍、启用扰动。六组均从随机权重开始，使用 seed 0 和 256 环境。报告至少包含 1024 个完整 episode。没有更新次数上限，也不晋级到 S2。达到 80% 后继续记录保持情况。

| 组名 | 相对基线的更改 | 比较范围 |
|---|---|---|
| baseline | 仅包含共同时间修复 | DCOL、H150、完整 2 秒速度窗口 |
| velocity_ema | EMA 替换完整速度窗口 | 速度监督设计 |
| relative_lateral | 显式相对接近速度、横向项系数 1 | 两项组合，不能单独归因 |
| risk_speed | 在 relative_lateral 上启用最低 0.25 的目标速度比例 | P3 的增量作用 |
| without_dcol | 动态 DCOL 替换为原始几何 SDF 减半径 | 采样时刻、终端规则和静态距离不变 |
| shac | H32、逐步速度、失败成本 300、boundary_huber、target tau 0.005、critic 8 次且最多 16 步 | SHAC 修复方案，属于多变量方法对照 |

共同 actor 学习率为 0.001，cosine 周期为 400 次更新。SHAC 保留真实终止 bootstrap 为 0、timeout 使用重置前端点的规则。失败成本 300 来自此前诊断的候选，不能保证全状态下不会提前终止。该组尚需以完整 episode 的成功率和失败类别判断修复效果。

六组按显存容量依次初始化。启动器记录各次启动时的并发数。墙钟比较包含启动和训练，使用 `process_elapsed_s`。并发数会影响单次更新耗时；本轮不是独占 GPU 的吞吐基准。

## 日志和验收

队列默认生成 `logs/curriculum/YYYY-MM-DD_HH-MM-SS_comparison`。显式指定输出目录时，也应使用时间前缀。同一实验的课程阶段共用 `<run>/zhang/tensorboard`。成功率统一为 `Train/success_rate`；课程编号单独记录。历史事件文件、检查点和失败试验保留。

训练成功率仍按完整 episode 汇总。`Train/episodes` 是当前报告的分母。首次达到 80% 与后续保持情况分别报告。损失下降、单次更新通过和短时轨迹均不构成学习验收。

CPU 检查通过 444 项测试及 520 项子测试。定向测试覆盖未来障碍越过查询点后的梯度反向。静态速度、水平奖励、EMA 重置及更新边界均有测试。测试还覆盖 SHAC 的 EMA 记忆、终端位置和日志标签。

真实 PhysX 检查使用 32 环境，每组 2 次更新。BPTT 检查 H48，SHAC 检查 H32。六组均通过，共核验 139,264 个中间采样点及 17,408 个终端采样点。中间点核验预测位置，终端点核验真实子步位置。分项梯度和总梯度的最大相对误差为 1.60e-7。六组均无非有限梯度，动作执行差为 0。另从实际事件文件检查了统一标签。结果见 [结构化证据](results/TIME_ALIGNED_AVOIDANCE_20261030.json)。

首轮的 SHAC 因检查脚本未创建日志目录而未启动，失败日志保留。修正后，六组完成两轮短检查，其中一轮启用梯度诊断。这些检查不构成训练效果比较。

本轮不执行 H、cosine 长度或课程阈值的参数扫描，训练收益需等待成功率与墙钟记录。
