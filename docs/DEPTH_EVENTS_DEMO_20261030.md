## “便宜的自运动补偿深度历史”是什么

先把旧深度像素恢复为相机坐标中的三维点。再用两帧的自身位姿，把旧点投到新相机坐标系。最后比较新测量与重投影深度。这样可先扣除无人机移动造成的图像变化。无需训练新网络，也无需先分割完整物体。

这套处理使用已收到的深度、时间戳和相机标定。自身位姿来自机载状态估计。未知区域不会从当前场景补齐。具体输入时间、缓存 reset 和检查点约定见 [共享扰动与观测时间](SIM_TO_REAL_TRAINING.md)。

“部署时拿不到的信息”通常称为特权信息（privileged information）。全局障碍位置、真实速度、物体 ID 属于这类信息。默认补偿不读取这些量。仿真用带噪自身真值模拟里程计；这是假设存在机载估计器，并未运行真实 VIO。

补偿采用配置中的名义相机安装外参。固定训练阶段的相机安装随机偏差为 0。旧随机化模式中的 1° 安装误差不会被偷偷补偿。内参按已知相机标定处理；部署时需提供对应标定。

收到旧图像后，补偿可以更新其中静态点的观察坐标。补偿不能推断未知障碍物在延迟期间的运动，也不能恢复新显露区域。图像帧龄仍记录为 0/50/100 ms，不会被清零。

## 二值事件方案的审核

保留原深度，再加一个二值通道，这个输入设计可行。值 1 表示检测器确认了运动线索。值 0 表示未确认，不能解释为静止。慢运动、遮挡、视野边缘和历史不足都可能造成漏检。

M-detector 使用点云历史、位姿和遮挡关系识别运动事件。论文区分逐点事件检测与整帧运动分割。二者都不是障碍物真实速度。相机帧差也不等同于 M-detector。[原论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC10771495/)、[官方源码](https://github.com/hku-mars/M-detector)

本 demo 调用了本机现有的原生 M-detector 扩展。界面分别显示逐点事件标签和整帧运动标签。同时显示未经补偿的帧差，以及便宜的补偿后深度变化。后者只检测靠近或进入的表面，不能等同于完整 M-detector。

用于演示的策略张量是 `2×12×16`：原逆深度＋二值运动标签。池化时，标签来自所选最近深度点。不能把背景运动标签贴到同一格的静态近点上。正式策略仍使用原单通道深度。

## Demo 条件与结果

四种场景都包含无人机平移和偏航。相机为 160×120、20 Hz。障碍包含静态圆柱和高 5 m 的运动圆柱。每种场景运行 100 帧，前 20 帧预热。检测器仅收到可见深度点、标定、位姿估计和时间戳。真值标签只用于评分。

位姿估计在此 demo 中无噪声。参数沿用现有 LiDAR 配置，并适配帧率、视野和缓存。深度相机的检测阈值尚未标定。因此以下结果只描述这次接入，不代表 M-detector 的最佳性能。

补偿后深度变化每帧 CPU 中位耗时约 3.4–3.5 ms。原生 M-detector 在横穿、迎面场景约为 79.7、72.6 ms，超过 20 Hz 的 50 ms 周期。这些计时来自共享负载机器，不是独占硬件基准。逐帧调用也不能直接继承论文逐点事件的微秒级延迟结论。

结果支持把二值通道作为候选输入。当前漏检与计算耗时不支持直接启用训练默认，更不能只保留“运动点”来避障。静态障碍仍需要原深度。

更小的下一步是保留带符号的补偿后深度差，再附有效标记和帧龄。这样可保留变化幅度与方向线索，避免阈值过早丢弃信息。深度差仍不等于物体速度，遮挡边缘尤其如此。该扩展尚未编写；本次交付限于要求的二值 demo。

## P0 与相对运动

P0 是此前已完成的动态障碍前视时刻修复。前视时刻 τ 的距离，必须同时推进无人机与障碍物：

\[
d(\tau)=D(p_u+v_u\tau,\ p_o+v_o\tau).
\]

修复前只推进无人机。修复后，相邻前视距离的差分包含双方运动。若 n 从障碍指向无人机，距离变化率近似为 `(v_u-v_o)·n`，接近速度则取其负值。沿连线双方以 1 m/s 迎面运动时，距离每秒减少约 2 m；同向同速时约为 0。

因此基线避障损失的距离差分已包含相对运动信息。这不表示 actor 直接看到了障碍速度。最近障碍切换和离散采样会影响差分，速度权重的下限还会压平低接近速度之间的差异。
