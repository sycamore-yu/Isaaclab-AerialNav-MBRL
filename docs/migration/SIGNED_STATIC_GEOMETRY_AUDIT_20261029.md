## 3. 为什么不能称作精确 SDF

原始网格最近点可能落在保守占据的内部折叠面上。给最近距离加负号会把该内部面错误地变成零距离“出口”：位置梯度把无人机拉向内部面，穿过该面后又可能反向，无法表达离开占据区域的方向。

最高投影占据也不等于任意实际三角网格的三维实体。合法悬垂表面下方可以存在空气腔；最高投影会填满这类空腔。因此“两侧均 inside”并不自动证明整个面都可以删除。本次实际地图还包含已严格证明的非共面自交，单纯改成绕数符号、同时继续使用所有原面求最近点，也不能自动解决内部面的错误出口。

同样不能把各个小凸体的 SDF 取最小值就称作精确 union SDF。一个简单反例是区间 `A=[-2,1]`、`B=[-1,2]`：在 `x=0`，两者 signed distance 的最小值为 `-1`，而真实并集 `[-2,2]` 的距离为 `-2`；前者在中间产生错误的局部最高值。网格小单元的内部界面会造成相同问题。

精确外壳方案需要完整处理相交线、共面重叠与部分遮盖，然后对分割后的面片确定实体边界。本轮没有引入这样的通用网格布尔修复，也没有将整个原面按其面心分类后删除。

## 4. 本轮选定的训练代理

设 `h(x,y)` 为该 XY 上原始投影非零三角形的最高竖直命中高度。训练占据定义为：

```text
Ω = { (x,y,z) : 原网格在该XY有投影命中，并且 z < h(x,y) }
```

没有投影命中的位置不做最近高度填补，也不使用整个地图包围盒把空洞填成实体。地面仍由既有独立 signed-ground 项处理。

代理按以下规则计算：

1. **Ω 外：** 使用完整原网格的精化无符号最近距离。零厚薄片仍可产生避障信号，不因为两侧都是 outside 而被删除。非零距离的数值及位置导数与修正后的canonical查询一致；不保留旧FP32切向漂移。精确落在零距离表面时选取有限法向作为逃逸次梯度。
2. **Ω 内：** 首先检查原网格最近点 `q` 是否确为选定方向上的出口。非零距离时方向 `u=(q-p)/||q-p||`；要求 `q-εu` 在 Ω 内且有数值余量，`q+εu` 在 Ω 外且有数值余量。候选验证使用第8节的clearance guard，但Ω本身仍按严格 `z<h` 定义。检查的是候选点自身，不能用整张三角形的面心是否暴露来代替。
3. **内部零距离：** 对实际点沿候选面法向的正反方向验证出口。若两侧仍 inside，不能接受该内部片的 `-0`，必须继续找出口。
4. **异常搜索：** 在局部 BVH 候选中检查原三角形的投影点、面心以及边上的最近点，每个候选都独立验证。搜索扩张到最多 `min(屋顶距离, 2 m)`，防止 continuous 深埋点扩大查询到整片地图。这个 2 m 上限只限制异常候选搜索，普通已验证的原最近点不受它裁剪。部分遮盖面可以有合法和非法部分，不通过删除整面解决。
5. **最终退路：** 采用同一 XY 上最高竖直命中的真实屋顶点，并验证其向上的出口方向。这个点来自原网格，不生成新的竖直封闭面。若没有更近合法候选，屋顶提供保守的逃逸方向；不声称它是数学上最近的出口。屋顶本身可以在 2 m 以外，局部搜索上限不把它改成虚构的近处 anchor。
6. **失败阻断：** inside 样本若最终没有通过出口验证，返回距离被置为 `NaN`，进入既有 rollout loss/有限性检查；不继续使用未验证的负距离，也不为每个策略查询额外增加 host/GPU 同步。

内部代理值为到选定出口的负距离。几何选择与出口 anchor 均 detached，位置保留指向该出口的导数。返回的 `mesh_closest_point` 与 `closest_point` 分别允许检查原最近点和实际选中出口；`exit_valid` 与 `used_exit_search` 用于验证出口合法性和异常搜索覆盖。

有限距离探针只有数值容差意义。当前探针尺度至少为 `1e-4 m`，并随 float32 世界坐标尺度调整；它不是任意薄几何的精确拓扑证明。不能把放宽该尺度当作消除实际失败的修复。

### 明确的数学限制

该定义保守填充最高投影之下的部分空气，因此不等价于所有真实 3D 空腔的自由空间。搜索只检查有限候选，也不保证找出最近的合法外壳片段。

Ω 的投影边界可能包含原网格没有的竖直封闭面。本实现不添加该面，所以内部出口负距与 Ω 外的原始正距可能在这类边界处跳变。代理不保证全局连续、1-Lipschitz 或具有精确 SDF 的所有性质。

冻结出口的导数是训练所用的逃逸方向。例如斜屋顶的竖直 fallback，其 anchor 随重新查询的 XY 变化，但当前反向不包含这个选择过程的导数。因此普通平面点的 finite-difference 检查通过，不能推导出每个 fallback 都等于重新查询标量函数的完整导数。实现和元数据统一使用 `signed_heightfield_occupancy_exit_proxy`，不得改称通用自交网格 SDF。

## 8. 真实近壁查询的精度修复

v2/v3实际300地图出口检查保留了另一项失败：51,657个查询中25,875内部点均有合法出口，方向复查错误数0，但原网格closest复查残差最大0.00014355649 m。独立float64计算证明导出的5个anchor都在原mesh上，残差来自Warp单精度投影沿面的漂移。

更关键的是第一次投影也会污染方向。在真实0.1 m宽、5.9 m高、世界坐标约−15 m的竖直三角面旁，法向距离约99.182 μm，原最近点z方向漂移61.035 μm，距离高估17.43%；应为水平的[0,−1,0]逃逸方向带入约+0.524的竖直分量，偏角31.62°。这是近壁诊断点的明确数值错误，不足以单独解释此前全部训练高度失效。

两个查询入口现在对BVH选中的原三角形执行float64平面投影、主法向轴对应的二维重心判断以及三条边的截断投影，最后一次转回float32。异常出口搜索的候选投影也共用此计算。后续400实测还发现BVH在近并列情况下选错面：一个实际在原mesh上的anchor被重查为距离约99.897 μm。现在精化seed距离不超过2 mm时，枚举2.01 mm AABB内全部原面并在float64中取更近投影，同时返回获胜面以计算零距离法向。10 μm包围盒保护只处理舍入；深部查询不增加这次扫描，不宣称任意距离上的全局最优。

外部parity比较对象是同一未改网格上的**修正后canonical无符号查询**，不再宣称与旧float32舍入错误逐位相同。原出口合法性、2e-5 m归属残差和真实侧面方向检查保留；新增CPU/CUDA回归以真实垂直平面为解析答案，要求切向坐标与纯水平梯度精确一致。

复核代码：[audit_static_anchor_precision.py](../../tests/audit_static_anchor_precision.py)；原始五点、实际邻近三角形及独立结果：[精度记录](../results/zhang_static_projection_precision_20261029.json)。最新通过状态以[验证索引](../results/zhang_restart_validation_20261029.md)及实际JSON为准。

400场景另有一个擦边候选：内侧探针的z约0.9309581518 m，最高投影约0.9309577942 m，仅相差0.358 μm，Warp候选检查与独立Torch探针的inside判定不一致。不能由该证据唯一断言FMA是原因。修复只强化出口接受条件：内侧高度差、外侧高度差都需超过 `max(1e-6, 8*eps32*ray_endpoint_scale)`；没有外侧投影命中时仍为outside。两张地图的guard为6.675720 μm，前后探针仍为100 μm；Ω定义、原网格归属阈值与独立方向检查均保持。该余量是数值稳健措施，不是对任意近竖直三角形的严格误差上界。拒绝擦边候选可能选择稍远的真实出口，仍不声称精确SDF。
