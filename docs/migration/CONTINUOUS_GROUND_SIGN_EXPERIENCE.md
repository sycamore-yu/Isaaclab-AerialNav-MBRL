# 连续展开穿过地面后的距离符号经验

日期：2026-10-29。适用范围是 Zhang continuous：无人机不发生 PhysX 接触响应，碰撞和高度越界不重置，动力学继续推进。此修正不改变五阶段课程、首次失败锁存、无效状态与超时重置、七项损失形式或系数。

## 为什么非饱和高度项仍不足以保证恢复方向

冻结提交 `50766ecfc9b7971ee2a7e64d9f5ed45fd3cd43f5` 已将高度项改为 SmoothL1。该项在远越界时仍有正确梯度，但总损失还包含避障和碰撞项。原最近点向量取欧氏范数，默认地面使用 z=0.01 m 的平面，实际静态地形平面约为 z=0 m。地面以下的无符号距离随继续下降而增大，优化器因此可能通过下降来减小避障成本。

在静止、无动态障碍的平面合成场景中，使用正式默认系数（avoidance=3、collision=7.5、height=1），z=-0.1 m 处的加权位置导数为：

| 项 | 原 continuous 的 dL/dz | 含义 |
| --- | ---: | --- |
| 避障 | +7.2 | 梯度下降继续向下 |
| 碰撞 | +239.6019 | 梯度下降继续向下 |
| 高度边界 | -2 | 梯度下降向上 |
| 总和 | +244.8019 | 错误的总恢复方向 |

因此不能由“高度梯度不饱和”推断“总梯度一定恢复高度”。这也是把原本会被reset截掉的状态变成可连续访问状态后，必须重新检查损失定义域的原因。

这里的方向问题不是整个地下空间都缺失恢复梯度：远离地面后原无符号碰撞/避障项衰减，高度项仍向上；但在地面下附近会出现错误方向和伪局部极小。合成平面例子的伪局部极小约为 z=-0.9667 m。实际群体训练曲线不能单独证明每个失败轨迹都停在这个位置。

## 最小修正

在原策略步开始时、原10个look-ahead查询点上保存
`ground_signed_distance = query[..., 2] - 0.01`。必须保留这个query的可微图，不能使用终止后或reset后的高度代替。

只对continuous执行：

```python
signed_clearance = ground_signed_distance - margin
distance = torch.where(ground_signed_distance < 0, signed_clearance, original_distance)
```

然后沿用原来由distance差分得到的approach权重、平方避障项和Softplus碰撞项。两项共享修正后的距离，避免只修碰撞而保留反向避障梯度。高度项保持原公式。

整条查询都在地面以上时，原值与原梯度保持；step和dcol完全不读取新字段。continuous严格要求新历史字段及其形状，缺失时明确报错，避免集成遗漏后静默回退。

此修正针对平面的物理半空间，不声称解决非凸静态地形内部的穿透距离。dcol的碰撞项本来就使用有符号地面gap，但其原避障项仍保留无符号距离；本次不改变dcol的损失，以保持正在进行的对照定义。

## 真实场景验证方法

`tests/new_mechanisms_scene.py` 的continuous分支将一架无人机手工放到实际地形平坦边缘的地面下，再推进两次PhysX策略步。检查episode保持、机体继续运动、首次失败及时间不变，并把实际mesh最近点查询与修正损失连起来，检查避障、碰撞、高度及总项对起点位置的恢复梯度。

相机仍输出有限原始深度和策略输入。该检查使用现有对齐的可微代理，不是可微PhysX接触；手工放置和梯度检查不是策略成功恢复的证明。结果必须在关闭Isaac Sim之前写入JSON，只有退出码而没有通过断言的JSON不算通过。
